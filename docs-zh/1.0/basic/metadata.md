<em class="lead">附着于一切上的开放通道：它承载什么、如何合并、落在哪里</em>

协议中几乎一切都携带一个 OPTIONAL 的 `metadata` 对象——事件、消息、
工具调用、工具、中断、恢复条目。它是协议未建模之物的开放通道：提供方
名称、时延、结束原因、token 计数、追踪键，以及应用想让任何东西随其
数据同行。

## 值 {#the-value}

`metadata` 按键开放。一个键之下允许任意 JSON 值，包括 `null`——那里的
`null` 是有意义的数据。对象本身要么缺失，要么是一个对象，MUST NOT
为 `null`。

未知的元数据键是协议合法的，而非未识别的材料：[处理模型](../basic/processing.md)
永不剥离它们，对任何键都如此。

## 键 {#keys}

`ag-ui` 键为协议自身保留。其他所有键都属于应用空间；生产方 SHOULD
为自己发明的键加上厂商或应用名称前缀，以免扩展同一条事件流的两方
发生冲突。

## 合并 {#merging}

一个流式项由多个事件组装而成，而有价值的信息——token 用量、一个结束
原因——只在结尾才可知。因此元数据是累积的，而非在项开启时固定：
消费方 MUST 合并构成一个项的每个事件的元数据，逐键进行，每个键上
最后一次写入获胜。

合并 MUST NOT 递归。一个键的值被整体替换，因此一个键之下的对象或
数组是被整体替换，而非与之前的内容混合。

## 每个事件的元数据落在哪里 {#where-each-event’s-metadata-lands}

合并需要目标，而目标就是该事件所构建的东西——并不总是消息：

| 事件 | 合并到 |
| --- | --- |
| `TEXT_MESSAGE_START` / `CONTENT` / `END` | 该文本消息 |
| `REASONING_MESSAGE_START` / `CONTENT` / `END` | 该推理消息 |
| `TOOL_CALL_START` / `ARGS` / `END` | **工具调用本身** — 而非拥有它的那条助手消息 |
| `TOOL_CALL_RESULT` | 它创建的那条工具消息 |
| `ACTIVITY_SNAPSHOT` / `ACTIVITY_DELTA` | 该活动消息 — 累积的元数据在替换性快照之后仍然存活（[活动](../events/activity.md)） |
| 块（`*_CHUNK`） | 它们的合成事件合并到的那个东西（[块元数据](../basic/patterns/streaming.md#chunk-metadata)） |
| 其他一切（`RUN_*`、`STEP_*`、快照、`RAW`、`CUSTOM`、…） | 无 — 见下文 |

::::
工具调用的元数据落在调用上而非其父消息上是刻意的。一条助手消息可以
拥有多个工具调用，因此把它们的元数据折叠进父消息会让结果取决于调用
碰巧交错成的顺序。每个调用各自保留自己的元数据，正是它保持无歧义的
原因。
::::

一个不构建持久项的事件没有合并目标：它的元数据就是该事件自己的，
可见于中间件和任何观察事件流的一方，协议不再把它指派到别处。
消费方 MAY 呈现它——例如把某次运行的 `RUN_FINISHED` 元数据放进
自己的簿记——但没有规则要求这样做。

## 存储的元数据 {#stored-metadata}

消息、工具调用、工具、中断和恢复条目把 `metadata` 作为它们自己的普通
存储字段携带。除上述列出的事件外，没有任何东西合并到它们之中；
一个工具的元数据（在[运行输入](../basic/run-input.md) 中）或一个
中断的元数据，只是随其载体同行的数据。

## 数据类型 {#data-types}

[`Metadata`](../schema.md#metadata) 由
[schema 参考](../schema.md) 定义，且每个载体的条目中都列出了
它的 `metadata` 字段。
